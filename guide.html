Сад за 5 минут

Гайд для студентов: что кликать, как читать растения и как не заблудиться. Никаких знаний о сетях не нужно.

Открыть сад

Маршрут: 5 шагов

Делай по порядку. Каждый шаг — одно действие.

1Осмотрись

Ты в саду. Каждая светящаяся фигура — сетевой протокол (правило, по которому компьютеры общаются).

Управление мышью: колесо — приблизить, тянуть фон — осмотреться, двойной клик — вернуться назад.

2Кликни самое большое дерево слева

Это IPv4 — фундамент интернета. Справа откроется карточка. В ней сверху вниз:

номер RFC и год → название → статус → описание человеческим языком → связи («зависит от», «используется в») → ссылка на оригинальный документ.

Открыть IPv4 в саду →

3Пройди по корням

В карточке IPv4 найди раздел «Используется в» и кликни TCP. Камера сама подлетит к нему.

Пунктирные линии между растениями означают «построен на основе»: TCP растёт из IPv4, а HTTP — из TCP. Целое дерево зависимостей!

Открыть TCP в саду →

4Включи фильтры

Вверху экрана — кнопки. Нажми Transport: останутся только 3 растения (TCP, UDP, QUIC). Нажми Все уровни — всё вернётся.

В строке поиска набери http — останутся 4 протокола. Клавиша Esc закрывает карточку, клавиша / ставит курсор в поиск.

5Проверь себя

Три задания. Ответы спрятаны — сначала попробуй сам в саду.

Задание 1: какой протокол самый «большой» и почему?

Подсказка: размер растения = количество связей. Ответ: TCP — у него больше всех зависимостей (на нём стоят HTTP, SMTP, SSH и другие). Найди самое крупное растение-«лиану» в середине сада.

Задание 2: пройди путь письма — от почтовой программы до проводов

Ответ: SMTP → TCP → IPv4. Найди SMTP поиском, открой карточку и иди вниз по разделу «Зависит от»: SMTP зависит от TCP, а TCP — от IPv4.

Задание 3: что общего у HTTP/2 и HTTP/3?

Ответ: оба — «цветы» прикладного слоя, оба заменили предыдущую версию. Но HTTP/2 стоит на TCP, а HTTP/3 — на QUIC. Сравни их карточки: раздел «Зависит от».

Анатомия растения

Каждое растение собрано из пяти слоёв — и каждый живёт по-своему.

Корни — связи

Светящиеся нити вниз — зависимости растения. Тускнеют, когда растение вне фокуса.

Стебель — жизнь

Слегка качается, внутри бегут частицы-соки снизу вверх.

Листья — дыхание

Кристаллические пластины раскрываются и закрываются не в такт друг другу.

Цветок — антенна

Лепестки медленно вращаются, ядро пульсирует. В фокусе цветок раскрывается шире.

Плоды — польза

Светящиеся сферы: сколько узлов стоит на этом. Клик по плоду открывает карточку.

Статусы — жив ли протокол

активен  — стандарт живой, используется прямо сейчас (TCP, DNS).

обновлён  — работает, но есть более новая версия (HTTP/1.1 → HTTP/2).

устарел  — музейный экспонат, почти не используется (FTP).

Связи и частицы

Пунктирная линия между растениями = «зависит от». Градиент цвета показывает, кто с кем связан.

В карточке четыре вида связей: зависит от (корни), используется в (ветви), заменил / заменён на (история).

пример пути пакета: HTTP/2 → TCP → IPv4 (цветок → лиана → дерево, сверху вниз — как вода по корням)

Светящиеся точки, бегущие по линиям, — частицы данных: так пакет проходит стек протоколов.

Частые вопросы

Я ничего не знаю о сетях. С чего начать?

С шагов 1–3 выше. Потом открой Обучение — там разбор на примере открытия сайта.

Что за номер RFC?

RFC (Request for Comments) — номер официального документа-стандарта. Первый вышел в 1969 году. В карточке есть ссылка «Читать оригинальный RFC».

Как поделиться конкретным протоколом?

Открой его карточку и нажми кнопку «поделиться» вверху — ссылка с хешем (например, explore.html#rfc0793) скопируется в буфер.

Глоссарий за минуту

Слова, которые встретятся в саду.

Пакет

Кусочек данных в конверте с адресами «от» и «кому». Всё в сети ездит пакетами.

IP-адрес

Адрес компьютера в сети. IPv4: 4 числа (192.168.1.1). IPv6: длинный, с двоеточиями.

Порт

Номер «двери» в компьютере: 80 — веб, 25 — почта. IP выбирает дом, порт — дверь.

Сокет

IP + порт вместе. Точный адрес программы, а не просто машины.

Handshake

Рукопожатие: стороны договариваются, прежде чем слать данные (у TCP — тройное).

Стек

Слои протоколов друг над другом: каждый пользуется нижним. HTTP → TCP → IP.

NAT

Переводчик адресов на роутере: прячет домашние адреса за одним внешним.

DNS

Телефонная книга интернета: имя → IP-адрес.

Шифрование

Перемешивание данных так, чтобы чужой видел шум. Расшифровать может только свой.

Токен

Пропуск вместо пароля: сайт верит токену, а пароль не видит.

Зависимость

«Стоит на»: протокол не работает без нижнего. Пунктир в саду.

RFC

Номер документа-стандарта. Первый — 1969 год. Ссылка на оригинал есть в каждой карточке.
