Семейства и разновидности

Шесть семейств закрывают почти всё, что встретится в продакшене.

Debian-семейство

Кто: Debian, Ubuntu, Linux Mint, Kali, Raspberry Pi OS, Proxmox VE

Пакеты: apt, формат .deb

Службы: systemd. Сеть: netplan (Ubuntu Server) или NetworkManager

Где: веб-серверы, десктопы, стенды labspin и сам Proxmox — он собран на Debian

RHEL-семейство

Кто: RHEL, Rocky Linux, AlmaLinux, Fedora, CentOS Stream, Oracle Linux

Пакеты: dnf (yum — старое имя), формат .rpm

Службы: systemd. Сеть: NetworkManager. Плюс SELinux и firewalld

Где: корпоративные серверы, банки, госсектор — там, где нужна поддержка 10 лет

Arch-семейство

Кто: Arch Linux, Manjaro, EndeavourOS

Пакеты: pacman, rolling-release (всё самое свежее)

Службы: systemd, настройка вручную

Где: рабочие станции энтузиастов, тестовые стенды. Правило: обновляться только целиком

SUSE-семейство

Кто: openSUSE Leap, openSUSE Tumbleweed, SLES

Пакеты: zypper, формат .rpm

Службы: systemd. Фишка: YaST — панель управления в терминале

Где: европейский enterprise, SAP-окружение, инженерные компании

Alpine

Кто: Alpine Linux

Пакеты: apk. Библиотека musl вместо glibc, утилиты BusyBox

Службы: OpenRC — systemd здесь нет!

Где: контейнеры Docker, роутеры, встраиваемые системы — образ от 5 МБ

Gentoo

Кто: Gentoo Linux

Пакеты: emerge + Portage, всё компилируется из исходников

Службы: OpenRC или systemd на выбор, USE-флаги в make.conf

Где: максимум контроля и производительности, цена — время компиляции

Команды по семействам

Одна задача — разное написание. Свою колонку выучи наизусть.

Debian / Ubuntu — apt, ufw, netplan

sudo apt update && sudo apt upgrade -y # индексы, затем пакеты sudo apt install -y nginx curl # установка sudo apt remove nginx # удалить, конфиги останутся sudo apt purge nginx # удалить вместе с конфигами apt search nginx | less # поиск apt show nginx # карточка пакета sudo apt autoremove -y && sudo apt autoclean # чистка мусора sudo systemctl enable --now nginx # автозапуск + старт systemctl status nginx # жив ли journalctl -u nginx -f # живой лог службы sudo ufw enable # фаервол: сначала разреши SSH! sudo ufw allow 22/tcp sudo ufw allow 80,443/tcp sudo ufw status verbose # что реально открыто

Сеть Ubuntu Server: файл /etc/netplan/01-netcfg.yaml, применить — sudo netplan apply, проверить — ip a. Proxmox VE и стенды labspin живут именно здесь.

RHEL / Rocky / Alma / Fedora — dnf, firewalld, SELinux

sudo dnf upgrade -y # обновление sudo dnf install -y nginx curl # установка sudo dnf remove nginx # удаление dnf search nginx # поиск dnf info nginx # карточка пакета sudo dnf autoremove -y && sudo dnf clean all # чистка sudo dnf install -y epel-release # доп. репозиторий для Rocky/Alma sudo firewall-cmd --state sudo firewall-cmd --add-service={http,https} --permanent sudo firewall-cmd --add-port=22/tcp --permanent sudo firewall-cmd --reload && firewall-cmd --list-all getenforce # Enforcing | Permissive | Disabled sudo setenforce 0 # ТОЛЬКО для диагностики, временно! sudo ausearch -m AVC -ts recent # кого заблокировал SELinux

Сеть: NetworkManager — nmcli device status, nmcli con show. Постоянное SELINUX=enforcing правится в /etc/selinux/config, а не сносом защиты.

Arch / Manjaro — pacman

sudo pacman -Syu # ВСЕГДА полное обновление sudo pacman -S nginx # установка sudo pacman -Rns nginx # удалить с зависимостями и конфигами pacman -Ss nginx # поиск pacman -Qi nginx # что установлено sudo pacman -Sc # чистка кэша yay -S пакет # AUR: сторонний код — сначала читай PKGBUILD

Частичное обновление (pacman -Sy без -u) — классический способ сломать Arch. Фаервол ставится руками: ufw или firewalld, как выше.

openSUSE — zypper, YaST

sudo zypper refresh && sudo zypper update sudo zypper install -y nginx sudo zypper remove nginx zypper search nginx sudo yast # TUI-панель: сеть, службы, пакеты

Leap — стабильный (как RHEL по духу), Tumbleweed — rolling (как Arch по духу). Фаервол — firewalld, команды как у RHEL.

Alpine — apk, OpenRC

sudo apk update && sudo apk upgrade sudo apk add nginx curl sudo apk del nginx apk search nginx sudo rc-service nginx start # старт (systemd здесь НЕТ) sudo rc-update add nginx default # автозапуск — аналог enable

musl + BusyBox: легко и быстро, но glibc-бинарники и башизмы могут не встать. Сеть: /etc/network/interfaces.

Gentoo — emerge

sudo emerge --sync sudo emerge -avuDN @world # обновить всю систему sudo emerge -av nginx # установка с вопросом sudo emerge -C nginx # удаление

USE-флаги в /etc/portage/make.conf решают, с какими опциями соберётся пакет. Платишь временем компиляции за точный контроль.

systemd — везде, кроме Alpine и части Gentoo

systemctl status nginx sudo systemctl start|stop|restart|reload nginx sudo systemctl enable --now nginx # автозапуск + старт сразу systemctl is-enabled nginx # включён ли в автозапуск systemctl is-active nginx # работает ли сейчас journalctl -u nginx -f # живой лог journalctl -u nginx --since "1 hour ago" -p err hostnamectl # имя хоста timedatectl # время и NTP loginctl # сессии пользователей

Глубже: службы, логи, SSH, виртуалки

То, что отличает пользователя от администратора.

systemd глубже

systemctl list-units --failed # что упало после загрузки systemctl list-timers --all # systemd-таймеры (замена cron) sudo systemctl daemon-reload # после правки unit-файла — обязательно! sudo systemctl edit nginx --full # безопасная правка unit sudo systemctl isolate rescue.target # однопользовательский режим

Логи глубже

journalctl -p err -b # ошибки текущей загрузки journalctl --disk-usage # сколько жрут логи sudo journalctl --vacuum-size=200M # чистка dmesg -T | tail -30 # кольцо ядра: железо, OOM last | head # кто заходил sudo lastb | head # неудачные входы — брутфорс видно тут sudo tail -f /var/log/auth.log # Debian: входы и ssh sudo tail -f /var/log/secure # RHEL: то же самое

SSH: диагностика и защита

sudo sshd -t # проверка конфига ПЕРЕД рестартом! systemctl status sshd sudo journalctl -u sshd --since "30 min ago" chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys # /etc/ssh/sshd_config: PasswordAuthentication no PermitRootLogin prohibit-password # после правок: sshd -t, затем reload — он не рвёт сессии

От брутфорса — fail2ban (apt/dnf install -y fail2ban), от всего остального — только ключи.

Proxmox и виртуалки

qm list # все ВМ ноды qm status 100 qm start 100 qm shutdown 100 # вежливо; qm stop — жёстко qm snapshot 100 before-upgrade # снапшот — та самая страховка qm rollback 100 before-upgrade pct list # LXC-контейнеры

Стенды labspin — обычные qemu-ВМ на Debian-шаблоне. ID видишь в выводе qm list и в конфиге.

cron и таймеры

crontab -e # формат: m h dom mon dow — бэкап в 3:15 ночи: 15 3 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1 systemctl list-timers --all # systemd-альтернатива cron

В cron пустой PATH — только полные пути. Не сработало — смотри grep CRON /var/log/syslog.

nftables голыми руками

sudo nft list ruleset # все правила sudo nft add table inet filter sudo nft add chain inet filter input '{ type filter hook input priority 0; policy drop; }' sudo nft add rule inet filter input tcp dport 22 accept sudo nft add rule inet filter input ct state established,related accept

ufw и firewalld — лишь фронтенды над nftables. Правило живёт до ребута, если не сохранено (nftables.service / persistent).

Docker-минимум

docker ps # живые контейнеры docker ps -a # включая мёртвые docker logs -f web # лог контейнера docker exec -it web sh # зайти внутрь docker compose up -d # поднять по compose.yaml docker system prune -a # чистка (сносит неиспользуемые образы!)

Docker сам правит iptables — свои запреты проверяй в цепочке DOCKER-USER, а не в INPUT.

Сетевое ядро администратора

Работает почти везде: iproute2, ss, dig, tcpdump.

Интерфейсы, маршруты, сокеты

ip -brief a # адреса коротко ip r # таблица маршрутов sudo ip link set eth0 up # поднять интерфейс ss -tulpn # кто слушает (замена netstat!) ss -tunp | grep ESTAB # живые соединения

Связность и DNS

ping -c4 8.8.8.8 # жив ли узел mtr --report 8.8.8.8 # ping + traceroute в одном traceroute 8.8.8.8 # где теряется путь dig +short example.com # быстрый ответ DNS dig +trace example.com # вся цепочка резолва host example.com # коротко: имя -> IP resolvectl status # какой резолвер реально используется

Захват и проверка прикладного уровня

sudo tcpdump -i any -n port 80 # что летит по 80-му порту sudo tcpdump -i any -n host 192.168.10.10 curl -sSI https://example.com | head -20 # заголовки ответа nc -zv 192.168.10.10 80 # открыт ли TCP-порт iperf3 -s # сервер замера на одной стороне iperf3 -c 192.168.10.10 # клиент на другой ethtool eth0 # скорость и дуплекс линка

Где живёт конфигурация сети

RHEL / Fedora / SUSENetworkManager: nmcli, nmtui
Alpine/etc/network/interfaces, затем rc-service networking restart

WireGuard за 5 минут

# сторона A (сервер): wg genkey | tee privatekey | wg pubkey > publickey # /etc/wireguard/wg0.conf: [Interface] Address = 10.9.0.1/24 ListenPort = 51820 PrivateKey = ...ключ A... PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE [Peer] PublicKey = ...публичный ключ клиента... AllowedIPs = 10.9.0.2/32 sudo systemctl enable --now wg-quick@wg0 sudo ufw allow 51820/udp

AllowedIPs 0.0.0.0/0 у клиента — весь трафик в туннель; конкретные подсети — split-tunnel. Приватные ключи — как пароли: не в git!

Доступ и пользователи

Ключи, sudo, пароли, аудит входов.

SSH-ключи: полный цикл

ssh-keygen -t ed25519 -C "admin@web-01" # ключ (пароль-фраза — да!) ssh-copy-id user@host # отправить публичный ключ на сервер cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys # вручную, если без copy-id chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys eval $(ssh-agent) && ssh-add ~/.ssh/id_ed25519 # ключ в память на сессию

Приватный ключ никогда не покидает твою машину. Утерянный ноут = удалить его .pub со всех серверов.

sudo и группы без граблей

groups alice sudo usermod -aG sudo alice # Debian/Ubuntu sudo usermod -aG wheel alice # RHEL/SUSE/Arch echo "alice ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx" | sudo tee /etc/sudoers.d/alice sudo visudo -c # проверка синтаксиса — обязательно!

Файлы в sudoers.d — точечные права вместо ALL. Кривой sudoers = потеря sudo (чини через root-консоль или Proxmox).

Пароли и старение

sudo passwd -S alice # статус пароля sudo chage -l alice # срок действия sudo chage -M 90 -W 7 alice # жить 90 дней, предупредить за 7 sudo faillock --user alice # RHEL: счётчик неудачных входов sudo faillock --user alice --reset # разблокировать

На серверах с ключами пароль можно заблокировать вовсе: passwd -l alice — вход только по ключу.

Аудит входов

last | head # успешные входы sudo lastb | head # НЕудачные — брутфорс виден тут sudo journalctl _SYSTEMD_UNIT=sshd.service --since today | grep -iE "failed|accepted"

lastb пустой, а auth.log кипит — кто-то уже стучится. Дальше: fail2ban, ключи, смена порта — по желанию.

Диски и файловые системы

Разметка, LVM, здоровье, RAID.

Разметка и монтирование

lsblk -f # диски, разделы, ФС, точки blkid # UUID разделов # /etc/fstab — монтирование по UUID (буквы /dev/sdX плавают!): UUID=xxxx /data ext4 defaults,nofail 0 2 sudo mount -a # проверить fstab БЕЗ ребута! sudo umount -l /mnt # lazy, если занято

nofail для несистемных дисков — иначе зависнешь в emergency при сбое диска. mount -a после каждой правки fstab.

LVM: диски, которые растут

sudo pvcreate /dev/sdb sudo vgcreate vg0 /dev/sdb sudo lvcreate -n data -L 50G vg0 sudo mkfs.ext4 /dev/vg0/data # расширить на живую, без переразметки: sudo lvextend -L +20G /dev/vg0/data sudo resize2fs /dev/vg0/data # ext4; для xfs: xfs_growfs /data

Снапшоты тома (lvcreate -s) — страховка перед опасными операциями: откат за секунды.

Здоровье дисков

sudo apt install -y smartmontools # один раз sudo smartctl -a /dev/sda | grep -iE "reallocated|pending|health" sudo nvme smart-log /dev/nvme0 # для NVMe dmesg -T | grep -iE "I/O error|EXT4-fs error" # первые крики

Reallocated и Pending растут — диск под замену, бэкап сегодня. SMART не панацея: диски умирают и без предупреждения.

RAID коротко (и честно)

sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc cat /proc/mdstat # статус ресинка

RAID ≠ бэкап: защищает от смерти диска, не от rm -rf и шифровальщиков. На Proxmox зеркало делает нода (ZFS), внутри ВМ — один virtio-диск.

Консоль выживания

vim, tmux, grep, права в цифрах, пайпы, основы bash.

vim-минимум (и nano)

i — вставка; Esc — назад в командный режим :w — сохранить; :q — выйти; :q! — выйти БЕЗ сохранения u — отмена; yy — копировать строку; p — вставить; dd — вырезать gg — в начало файла; G — в конец; /текст + n — поиск :set number — номера строк # nano проще: Ctrl+O сохранить, Ctrl+X выйти

visudo, crontab -e и git открывают именно vim. Знать :wq и :q! — обязательный минимум.

tmux: сессия переживает обрыв SSH

tmux new -s deploy # новая сессия Ctrl-b d # открепиться — всё продолжает работать! tmux attach -t deploy # вернуться (хоть с другого ПК) tmux ls # список сессий tmux kill-session -t deploy # прибрать за собой

Долгий upgrade по SSH — только внутри tmux. Обрыв связи без tmux = прерванный dpkg (см. справочник проблем).

grep, find, sed, awk — разбор всего

grep -rni "error" /etc/nginx/ # рекурсивно, без учёта регистра grep -v "^#" nginx.conf | grep -v "^$" # конфиг без комментариев и пустых find /var/log -name "*.gz" -mtime +30 -delete # старше 30 дней — удалить sed -i.bak 's/80/8080/' file # замена с бэкапом .bak awk '{print $1}' access.log | sort | uniq -c | sort -nr | head # топ IP

Права в цифрах

# r=4 w=2 x=1 → суммы: 7=rwx 6=rw- 5=r-x 4=r-- 0=--- 755 каталоги и скрипты; 644 файлы; 640 секреты; 600 ключи; 700 ~/.ssh umask 022 → новые файлы 644, каталоги 755 umask 077 → максимум приватности chmod 1777 /tmp # sticky: удалять может только владелец chmod u+s /usr/bin/myapp # setuid — осторожно! find / -perm -4000 2>/dev/null # все setuid — проверь лишние

Читается слева направо: владелец, группа, остальные. Вопрос на собеседовании и в жизни: почему 777 — всегда неверный ответ.

Пайпы и перенаправления

cmd > out.log 2>&1 # всё в файл cmd >> out.log # дописать в конец cmd 2>/dev/null # скрыть ошибки cmd | tee out.log # и на экран, и в файл cmd1 && cmd2 # второе — только если первое успешно cmd1 || cmd2 # второе — если первое упало

Bash-минимум для скриптов

#!/usr/bin/env bash set -euo pipefail # падать на первой ошибке BACKUP_DIR="${1:?укажи каталог}" # обязательный аргумент if systemctl is-active --quiet nginx; then echo ok; fi for h in web-01 web-02; do ssh "$h" uptime; done # кавычки вокруг переменных!

Непроверенные переменные + rm -rf = карточка «Так делать не надо». Кавычки, set -u и :? — три страховки.

Установки от и до

Система, репозитории, пакеты, рабочий веб-стек, чеклист первого часа.

Сторонние репозитории по семействам

# Debian / Ubuntu: ключ + свой источник (без apt-key — он мёртв!) sudo install -m 0755 -d /etc/apt/keyrings curl -fsSL https://repo/app/key.gpg | sudo gpg --dearmor -o /etc/apt/keyrings/app.gpg echo "deb [signed-by=/etc/apt/keyrings/app.gpg] https://repo/app stable main" | sudo tee /etc/apt/sources.list.d/app.list sudo apt update # RHEL / Rocky / Alma: sudo dnf install -y epel-release sudo dnf config-manager --add-repo https://repo/app.repo # Arch: AUR через yay (читай PKGBUILD!) # openSUSE: sudo zypper ar https://repo/ alias # Alpine: дописать community в /etc/apk/repositories # Gentoo: eselect repository enable guru && emerge --sync

Мимо пакетника: deb, rpm, universal, исходники

sudo dpkg -i app.deb && sudo apt install -f -y # дотянуть зависимости sudo dnf install ./app.rpm # локальный rpm — правильно sudo rpm -ivh app.rpm # грубо, без зависимостей — так не надо snap install app # универсальные (Ubuntu) flatpak install flathub app # универсальные (везде) ./configure && make -j$(nproc) && sudo checkinstall # из исходников: checkinstall вместо make install!

Голый make install размазывает файлы мимо пакетника — потом не удалить чисто. checkinstall собирает из них .deb/.rpm.

Веб-стек за 10 минут (LEMP)

sudo apt install -y nginx certbot python3-certbot-nginx # RHEL: sudo dnf install -y nginx certbot python3-certbot-nginx sudo systemctl enable --now nginx sudo ufw allow 'Nginx Full' # Debian/Ubuntu # RHEL/SUSE: firewall-cmd --add-service={http,https} --permanent && firewall-cmd --reload sudo certbot --nginx -d site.example.com --agree-tos -m admin@example.com sudo nginx -t && sudo systemctl reload nginx curl -sSI https://site.example.com | head -5

Порядок важен: пакет → автозапуск → фаервол → сертификат → проверка. Сертификат обновляется сам (certbot timer), проверь: systemctl list-timers | grep certbot.

nginx: server-блок и прокси

# /etc/nginx/sites-available/site (Debian) или /etc/nginx/conf.d/site.conf (RHEL): server { listen 80; server_name site.example.com; location / { proxy_pass http://127.0.0.1:3000; proxy_set_header Host $host; } } # Debian: ln -s sites-available/site sites-enabled/ (в RHEL conf.d подхватывается сам) sudo nginx -t && sudo systemctl reload nginx tail -f /var/log/nginx/error.log # ошибки — сюда

reload, не restart — без разрыва соединений. Заглушка index.html в location / скроет упавший бэкенд от глаз, но не от мониторинга.

Новый сервер: чеклист первого часа

1Обновления: sudo apt update && sudo apt upgrade -y (или dnf upgrade -y)
2Имя: sudo hostnamectl set-hostname web-01
3Пользователь + SSH-ключи, PasswordAuthentication no (см. карточки выше)

Коды и значения ошибок

Что означают цифры: коды выхода, errno, HTTP, curl.

Коды выхода: читай через $?

./script.sh; echo $? # код прошлой команды # 0 — успех # 1 — общая ошибка # 2 — неверные аргументы # 126 — нет прав на запуск # 127 — команда не найдена # 130 — убит Ctrl+C (SIGINT = 128+2) # 137 — SIGKILL или OOM-киллер (128+9) # 139 — падение (SIGSEGV, 128+11) # 143 — SIGTERM (128+15) set -euo pipefail # скрипт падает на первой ошибке, а не врёт дальше

137 после ночи — почти всегда OOM-киллер: смотри dmesg, а не перезапускай вслепую.

errno: цифры ядра

# полный список: man 3 errno # 1 EPERM — операция запрещена # 2 ENOENT — нет такого файла # 13 EACCES — доступ запрещён (права!) # 17 EEXIST — уже существует # 28 ENOSPC — нет места на диске # 32 EPIPE — сломанный пайп # 98 EADDRINUSE — адрес уже занят # 110 ETIMEDOUT — таймаут # 111 ECONNREFUSED — в соединении отказано

HTTP-коды глазами админа

2xx200 OK, 201 создан, 204 без тела — всё хорошо
3xx301/302 редирект, 304 не менялось — смотри заголовок Location
400 / 401 / 403 / 404Кривой запрос / нет логина / запретили / нет страницы — чинится на стороне клиента и прав
500 / 502 / 503 / 504Упал код / мёртв бэкенд при живом фронте / перегруз или деплой / бэкенд виснет — чинится на сервере

Коды curl и ssh + разбор по стадиям

# curl: 6 — DNS, 7 — нет TCP, 28 — таймаут, 35/60 — TLS и сертификат curl -w "dns:%{time_namelookup} tcp:%{time_connect} tls:%{time_appconnect} total:%{time_total}\n" -o /dev/null -s https://site/ # видно, КАКАЯ стадия тормозит: резолв, handshake или ответ сервера # ssh: 255 — ошибка самого ssh (сеть, ключ); остальное — код команды внутри: ssh user@host 'cmd'; echo $?

Справочник проблем

Симптом, диагностика, лечение.

Нет сети вообщеНе пингуется даже шлюз. Иди по лестнице — ломайся на первой failed-ступени:
ip -brief a # 1. адрес вообще есть? ip r # 2. шлюз по умолчанию есть? ping -c3 <шлюз> # 3. L2 до шлюза жив? ping -c3 8.8.8.8 # 4. дальше шлюза ходит?

Нет адреса — смотри netplan / NetworkManager / DHCP. Нет шлюза — маршрут. Шлюз жив, а дальше нет — проблема уже не твоя машина.

DNS не резолвитIP ходят, имена — нет. Значит, дело точно в резолве:
ping -c2 8.8.8.8 # IP ходит, а имена нет = точно DNS resolvectl status # какой резолвер РЕАЛЬНО используется dig @1.1.1.1 example.com # обход локального резолва cat /etc/resolv.conf # 127.0.0.53 = stub systemd-resolved

Не правь resolv.conf руками — его перезапишут NetworkManager или systemd. DNS задаётся в netplan, nmcli или /etc/systemd/resolved.conf.

refused против timeoutРазные диагнозы — разное лечение:
ss -tulpn | grep :80 # слушает? и на чём: 127.0.0.1 или 0.0.0.0? nc -zv 127.0.0.1 80 # локально работает? nc -zv <внешний-ip> 80 # а снаружи?

refused = некому отвечать (служба down или bind на localhost). timeout = пакет умер по дороге (фаервол, маршрут).

Сайт не открываетсяРазбери, на какой стадии всё встало:
curl -sv https://site/ -o /dev/null # стадии: DNS -> TCP -> TLS -> HTTP echo | openssl s_client -connect site:443 2>/dev/null | openssl x509 -noout -dates -subject sudo nginx -t # конфиг веб-сервера валиден?

certificate expired или CN mismatch чинится обновлением серта, а не отключением проверки. 502 означает: nginx жив, мёртв бэкенд.

SSH не пускаетПричина почти всегда в логе sshd:
systemctl is-active sshd ss -tlnp | grep :22 sudo journalctl -u sshd --since "15 min ago" ls -ld ~/.ssh && ls -l ~/.ssh/authorized_keys # нужно 700 и 600

Неправильные права на ~/.ssh sshd игнорирует молча. После правок конфига — sshd -t и reload. Root по паролю наружу — нет.

Медленно, потери пакетовСмотри последний хоп, а не первый красный:
mtr --report --wide host # loss% по хопам ethtool eth0 | grep -i duplex # Half вместо Full — кабель или порт! iperf3 -c host # реальная полоса, а не ощущения

Потери на промежуточных хопах при чистом последнем — часто rate-limit ICMP, а не авария.

Диск кончилсяПроверяй и байты, и иноды:
df -h # где 100% df -i # иноды! миллион мелких файлов = та же авария du -sh /* 2>/dev/null | sort -rh | head sudo journalctl --vacuum-size=200M sudo apt clean # или: docker system prune

"No space left" при свободных гигабайтах — это иноды. Логи чистит vacuum, а не rm -rf /var/log: службы держат дескрипторы удалённых файлов.

Память кончилась, OOMЯдро убивает самый жирный процесс — узнай кого:
free -h dmesg -T | grep -i oom # кого убило ядро journalctl -k | grep -i "out of memory" # swapfile 2G: sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile sudo mkswap /swapfile && sudo swapon /swapfile

Лечится лимитами (MemoryMax в unit-файле) и swap, а не добавлением RAM вслепую.

Служба не стартуетВ 9 из 10 — опечатка в конфиге или занятый порт:
systemctl status svc --no-pager # exit-code и последние строки journalctl -xe -u svc # полный лог падения sudo nginx -t # валидация конфига ДО рестарта ss -tlnp | grep :80 # порт уже занят кем-то другим?

Проверка -t перед restart экономит даунтайм. Правило: сначала validate, потом reload.

Нагрузка CPU 100%Сначала пойми, кто и чего ждёт:
top # затем Shift+P (по CPU), Shift+M (по памяти) ps -eo pid,ppid,%cpu,%mem,comm --sort=-%cpu | head sudo apt install -y sysstat && iostat -xz 1 # диски тоже душат CPU

Высокий %wa в top означает ожидание диска, а не нехватку CPU. Лечится логами и диском, а не мощностью.

Время уплылоЛомает TLS, DNSSEC и Kerberos разом:
timedatectl # NTP synchronized: yes? timedatectl set-ntp true sudo systemctl enable --now chronyd # RHEL и SUSE

Симптом — «вчера работало». Причина — часы. На виртуалках время плывёт чаще: NTP обязателен.

Сломан пакетный менеджерLock-файл — мьютекс, а не мусор:
# apt висит на lock — жди процесс, НЕ удаляй lock-файл! ps aux | grep -E "apt|dpkg" sudo dpkg --configure -a # донастроить прерванное sudo apt install -f # починить зависимости sudo rpm --rebuilddb # RHEL: пересобрать базу rpm

Удаление lock-файла лечит симптом и калечит базу пакетов. Дождись процесса или убей именно его.

SELinux всё режетНе сносить, а точечно разрешить:
sudo ausearch -m AVC -ts recent sudo ausearch -m AVC -ts recent | audit2why # ЧТО за правило сработало sudo setsebool -P httpd_can_network_connect 1 # пример точечного разрешения

setenforce 0 навсегда — это сдача. Правильно: audit2why, затем bool через setsebool или контекст через semanage/chcon.

Забыл пароль rootНужен доступ к консоли (у ВМ — через Proxmox):
# в меню GRUB: клавиша e, к строке linux дописать: systemd.unit=rescue.target # либо для быстрого сброса: init=/bin/bash mount -o remount,rw / passwd root exec /sbin/init

Работает при физическом доступе или консоли Proxmox (qm terminal). На шифрованных дисках — только через recovery-ключи.

Permission deniedТри разные причины — проверь все по порядку:
ls -l файл # 1. права на сам файл namei -l /srv/app/config.yml # 2. ВСЯ цепочка каталогов (частая засада: нет +x на родителе!) sudo ausearch -m AVC -ts recent # 3. SELinux (RHEL): молчаливый запрет

Классика: файл 644, а каталог 700 у другого владельца. Лечит namei, а не chmod 777.

E: Unable to locate packageПакетника не знает такого имени:
sudo apt update # 1. индексы протухли? apt search имя | head # 2. точное имя другое? lsb_release -cs # 3. твой релиз есть в sources? (jammy vs noble!) grep -r "^deb" /etc/apt/sources.list*

После добавления репозитория всегда apt update. Нет пакета и после — нужен EPEL/AUR/сторонний репозиторий (см. выше).

GPG error: NO_PUBKEY / EXPKEYSIGПодпись репозитория нечем проверить:
# узнать ключ из текста ошибки (последние 8-16 hex-символов): sudo gpg --keyserver keyserver.ubuntu.com --recv-keys КЛЮЧ sudo gpg --export КЛЮЧ | sudo gpg --dearmor -o /etc/apt/keyrings/app.gpg # EXPKEYSIG = ключ протух: скачать свежий тем же способом

apt-key add мёртв — только signed-by в sources.list.d. Никогда не ставь [trusted=yes] чтобы «заткнуть» ошибку.

dpkg was interruptedПрерванная установка (упал SSH, кончилось место):
sudo dpkg --configure -a # донастроить прерванное sudo apt install -f -y # дотянуть зависимости
command not found (127)Три варианта, по вероятности:
apt search имя # 1. просто не установлено echo $PATH # 2. стоит, но не в PATH (/usr/local/bin? snap?) ls -l $(which имя) # 3. битая ссылка
user is not in the sudoers fileПользователя забыли в группе:
# из-под существующего sudo-пользователя или root: sudo usermod -aG sudo alice # Debian/Ubuntu sudo usermod -aG wheel alice # RHEL/SUSE/Arch # проверить: groups alice; перелогиниться!

Группа применяется при новом входе. Править /etc/sudoers — только через visudo (проверяет синтаксис, кривой файл = потеря sudo).

Job for X.service failedСлужба упала при старте:
systemctl status X --no-pager # exit-код и хвост лога journalctl -xe -u X # полная картина падения
Device or resource busyКто-то держит точку монтирования:
lsof +D /mnt/data | head # кто держит fuser -vm /mnt/data # процессы с PID sudo umount -l /mnt/data # lazy-отмонтирование, если спешишь
Read-only file systemДиск ушёл в RO — симптом, а не настройка:
dmesg -T | tail -30 # ошибки EXT4/SATA/NVMe? mount | grep " / " # проверить флаги # лечение: бэкап важного, затем fsck с live/USB; на ВМ — проверить сторадж ноды

Ядро переводит ФС в RO при ошибках, чтобы не портить данные дальше. Просто перемонтировать в rw — замести следы, а не починить.

Too many open filesПроцесс упёрся в лимит дескрипторов:
ulimit -n # текущий лимит shell cat /proc/PID/limits | grep -i open # лимит конкретного процесса lsof -p PID | wc -l # сколько реально открыто # навсегда: /etc/security/limits.conf или LimitNOFILE=65536 в unit-файле + daemon-reload
curl: (60) SSL certificate problemЦепочке не доверяют:
sudo apt install -y ca-certificates && sudo update-ca-certificates date # протухший серт ИЛИ уплывшие часы — проверь оба! echo | openssl s_client -connect site:443 2>/dev/null | openssl x509 -noout -dates

Флаг -k лечит симптом и убивает смысл TLS. Только для разового теста, никогда — в скриптах.

bind() failed: Address already in useПорт занят — найди кем:
ss -tlnp | grep :80 ps -fp PID # кто этот процесс # частая причина: второй nginx/apache или зависший мастер после kill -9
No route to host / Network is unreachableДополнение к refused/timeout:
ip r get 192.168.10.10 # каким маршрутом пойдёт? # Network is unreachable = нет маршрута вообще (шлюз? интерфейс down?) # No route to host = маршрут есть, сосед мёртв (фаервол режет ICMP? хост down?)

Четыре строки — четыре диагноза: refused (не слушает), timeout (фаервол/маршрут), unreachable (нет маршрута), no route (сосед мёртв).

Так делать не надо

Классические способы сломать сервер в первый день.

chmod -R 777 /«Чинит» права ценой безопасности. Правильно: найти владельца и выдать минимум.
curl … | sudo bashВслепую — никогда. Скачай, прочитай скрипт, потом запускай.
Выключить firewall / SELinux навсегда«Чтобы заработало» — чини правило, а не сноси стену. setenforce 0 — только диагностика.
Всё под rootКлючи + sudo вместо пароля root; 22-й порт наружу — только через bastion или VPN.
rm -rf $DIR/Пустая переменная превращает это в rm -rf /. Защита: ${DIR:?not set}.
Upgrade прода без снапшотаСначала snapshot в Proxmox, потом upgrade. Откат дешевле переустановки.
3306 / 6379 / 27017 в интернетБазы слушают 127.0.0.1 или VPN. Открытый Redis в мире находят за минуты.
Пароли в history и скриптахEnv-файлы с chmod 600 и HISTCONTROL=ignorespace (пробел в начале — не писать в историю).
