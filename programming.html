Git для автоматизатора

Ветки, отмена без паники, удалённые репозитории.

База: настройка и ежедневный цикл

git config --global user.name "Admin" git config --global user.email admin@example.com git clone git@host:repo.git git status -s && git add -A git commit -m "feat: ..." git push git pull --rebase # без merge-мусора в истории

Ветки

git branch feature/x && git switch feature/x git switch -c hotfix/y # создать и перейти сразу git merge --no-ff feature/x # слияние с узлом истории git branch -d feature/x # удалить после мержа

Правило: main всегда зелёный. Работа — в ветках, вливание — через ревью.

Отмена без паники

git restore file # откатить файл (не в коммите) git revert HEAD # отмена коммитом — безопасно для запушенного git reset --soft HEAD~1 # передумал про коммит, изменения целы git reset --hard HEAD # СТЕРЕТЬ всё несохранённое — осторожно! git reflog # журнал ВСЕХ движений — спасение утопающих

Stash: отложить грязное

git stash push -m "wip" # спрятать незакоммиченное git stash list git stash pop # вернуть git stash branch fix stash@{0} # продолжить в отдельной ветке

Удалённые репозитории и PR

git remote -v git fetch origin git log HEAD..origin/main # что приехало, до мержа git push -u origin feature/x # дальше — Pull Request в веб-морде

В main напрямую не пушат: ветка → PR → ревью → мерж. Так живут labspin и NetPulse.

blame, bisect, ignore

git blame -L 10,20 file # кто и когда правил строки git bisect start -- bad v1.0 good v0.9 # бинарный поиск коммита-виновника # .gitignore: *.log, .env, __pycache__/, *.pem — секреты и мусор не коммитят! git check-ignore -v file # почему файл игнорируется

Python для админа

Venv, безопасный subprocess, конфиги, логи.

venv и зависимости

python3 -m venv .venv && source .venv/bin/activate pip install -U pip && pip install requests pyyaml pip freeze > requirements.txt deactivate

Системный pip — только через venv. Debian вообще запрещает установку мимо venv (externally-managed-environment).

Скелет скрипта

#!/usr/bin/env python3 import argparse, logging, sys logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s") def main(host: str) -> int: logging.info("checking %s", host) return 0 if __name__ == "__main__": ap = argparse.ArgumentParser() ap.add_argument("host") sys.exit(main(ap.parse_args().host))

subprocess безопасно

import subprocess # правильно: список аргументов, без shell: subprocess.run(["ping", "-c", "2", host], check=True, capture_output=True, text=True) # shell=True + f-строка с вводом пользователя = инъекция команд

Так labspin запускает ping и ssh. check=True роняет скрипт при ненулевом коде — честное поведение.

yaml и json

import json, yaml cfg = yaml.safe_load(open("config.yaml")) # safe_load, не load! print(json.dumps(cfg, indent=2, ensure_ascii=False))

yaml.load без Loader выполняет произвольный код из файла. Всегда safe_load.

Логи и запуск

# logging в файл с ротацией: from logging.handlers import RotatingFileHandler h = RotatingFileHandler("app.log", maxBytes=2_000_000, backupCount=5) # долгоживущее — systemd unit с Restart=on-failure, а не cron

jq, yq и API

Разбирать и дёргать HTTP как профи.

jq: SQL для JSON

curl -s API | jq . # pretty-print jq -r '.vms[] | "\(.name) \(.ip)"' # строки без кавычек jq '.items | sort_by(.cpu) | reverse | .[0:3]' jq -e '.ok == true' > /dev/null && echo PASS # проверка в скрипте

curl по API

curl -sS -X POST API -H "Content-Type: application/json" -H "X-Auth: $TOKEN" -d '{"a":1}' curl -sSI https://site/ | head -5 curl --fail-with-body https://site/ # код не 2xx = ненулевой exit

-sS: тихо, но ошибки показывай. Так NetPulse ходит в Proxmox API.

yq: то же для YAML

yq '.vm_configs.stand1.network.ip' config.yaml yq -i '.checks.timeout = 10' config.yaml # правка на месте

Токены и секреты в скриптах

# токен — в env, не в историю: export TOKEN=... curl -sS -H "Authorization: Bearer $TOKEN" API # в Python: os.environ["TOKEN"] — KeyError лучше, чем тихий дефолт для секрета

Секреты не коммитят: .env + chmod 600 + .gitignore. Дальше — vault и DPAPI.

Редакторы вглубь

Регистры и макросы vim, окна tmux, regex, современный тулкит.

vim: регистры и макросы

"ayy — yank строки в регистр a; "ap — вставить из него qa ... q — записать макрос в регистр a; @a — выполнить; @@ — повторить :split и :vsplit, Ctrl-w w — hopping по окнам; :tabnew — вкладки ~/.vimrc: set number relativenumber tabstop=4 expandtab hlsearch

tmux: окна и автоматизация

Ctrl-b c — окно; Ctrl-b n/p — следующее/прошлое; Ctrl-b % и " — сплиты tmux new -s work \; split-window -h \; attach # раскладка одной командой ~/.tmux.conf: set -g mouse on

regex на каждый день

^[0-9]{1,3}(\.[0-9]{1,3}){3}$ # IPv4 (грубо, но работает) grep -P "sshd\[\d+\]: Failed" /var/log/auth.log sed -E 's/^# ?//' # раскомментировать строку
