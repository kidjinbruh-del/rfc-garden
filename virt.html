Proxmox вглубь

Хранилища, бэкапы, шаблоны, фаервол, HA.

qm: жизнь виртуальной машины

qm list / qm status 100 qm start 100 / qm shutdown 100 / qm stop 100 / qm reset 100 qm snapshot 100 clean --description "до обновлений" qm rollback 100 clean qm clone 100 200 --name stand-3 --full # full — независимая копия qm guest exec 100 -- ping -c2 8.8.8.8 # команда внутрь (нужен qemu-agent!)

Именно эти вызовы делает labspin через API. qemu-guest-agent в шаблоне обязателен — без него ни IP, ни exec.

Хранилища: типы и контент

# Datacenter → Storage → Add: dir / zfs / nfs / cephfs / lvm # У каждого типа — разрешённый контент: ISO, Images, Backup, Snippets pvesm status # что подключено и сколько свободно pvesm list local-zfs # что лежит внутри

ISO — только на file-хранилищах (dir/nfs). Диски ВМ — на блочных (zfs/lvm/ceph). Перепутал — получишь серую кнопку.

Бэкапы vzdump

# Datacenter → Backup → Add: расписание, storage, retention vzdump 100 --storage backup --mode snapshot --compress zstd # retention: keep-last=3, keep-weekly=4, keep-monthly=6 qmrestore backup/vzdump-qemu-100.vma.zst 200 # восстановить как новую ВМ

Snapshot-режим не останавливает ВМ. Проверяй restore раз в квартал — бэкап без проверки не считается.

Шаблоны и cloud-init

qm template 9000 # превратить настроенную ВМ в шаблон qm clone 9000 100 --name stand-1 --full qm set 100 --ciuser alice --sshkey ~/.ssh/id_ed25519.pub qm set 100 --ipconfig0 ip=192.168.10.10/24,gw=192.168.10.1 qm cloudinit dump 100 user # что реально уйдёт внутрь

Золотой образ: чистая ОС + qemu-agent + cloud-init, без ssh-ключей и history. Всё остальное — через cloud-init при клонировании.

Фаервол Proxmox

# Три уровня: Datacenter → Node → VM. Правила наследуются сверху вниз. # VM → Firewall → Add: Direction=in, Action=ACCEPT, Protocol=tcp, Dport=22 pve-firewall status # работает ли на ноде

Включишь на Datacenter — закроешь всё, что не разрешено явно. Сначала правило для 8006 и SSH, потом — кнопку.

HA и кворум

pvecm status # votes: нужно больше половины ha-manager add vm:100 --state started # ВМ под охраной HA ha-manager status

Две ноды без qdevice — split-brain при потере связи. HA без shared storage (ceph/NFS) — перезапуск, а не миграция.

KVM и libvirt

Сети, пулы, снапшоты руками.

virsh: Proxmox без морды

virsh list --all virsh net-list --all # сети (default = NAT virbr0) virsh pool-list --all # пулы дисков virsh snapshot-list vm1 virsh snapshot-revert vm1 --snapshotname clean virsh console vm1 # консоль (выход: Ctrl+])

Сеть libvirt

virsh net-dumpxml default # что за NAT virsh net-start default / virsh net-autostart default # мост на хосте вместо NAT — как vmbr0 в Proxmox (см. карточку про мост)

Диски qcow2

qemu-img info disk.qcow2 qemu-img create -f qcow2 -o preallocation=metadata disk.qcow2 20G qemu-img convert -O qcow2 disk.raw disk.qcow2 virsh vol-list default

qcow2 растёт по мере записи (thin). Снапшоты — только на qcow2, на raw их нет.

LXC-контейнеры

Лёгкая виртуализация в стиле Proxmox.

pct: база

pct list pct create 200 local:vztmpl/debian-12.tar.zst --hostname lxc-1 --net0 name=eth0,bridge=vmbr0,ip=dhcp --cores 1 --memory 512 --storage local-zfs pct start 200 / pct stop 200 pct enter 200 # зайти внутрь pct exec 200 -- systemctl status nginx

Привилегии и nesting

# unprivileged (uid-map) — по умолчанию и правильно # для Docker внутри LXC: Options → Features → nesting=1 pct push 200 /tmp/f.conf /etc/app/f.conf # закинуть файл внутрь pct pull 200 /var/log/app.log /tmp/ # забрать наружу

Привилегированный контейнер с пробросом /dev — почти рут хоста. Не надо так.

LXC против Docker и ВМ

LXCЦелая ОС, свой init, почти как ВМ — но без своего ядра. Идеален для сервисов labspin-стиля
DockerОдин процесс = один контейнер, образы из registry
VMСвоё ядро, любая ОС, максимальная изоляция — цена: гигабайты и минуты

Docker вглубь

Dockerfile, compose, сети, тома.

Dockerfile без граблей

FROM debian:12-slim RUN apt-get update && apt-get install -y --no-install-recommends nginx \ && rm -rf /var/lib/apt/lists COPY nginx.conf /etc/nginx/nginx.conf USER www-data EXPOSE 80 CMD ["nginx", "-g", "daemon off;"]

Один RUN на установку (меньше слоёв), чистка apt в том же слое, не root внутри. .dockerignore обязателен.

Compose: стек одним файлом

# compose.yaml: # services: # web: { build: ., ports: ["8080:80"], restart: unless-stopped } # db: { image: postgres:16, environment: { POSTGRES_PASSWORD_FILE: /run/secrets/pw } } docker compose up -d --build docker compose logs -f web docker compose down # стоп; down -v снесёт и тома!

Сети Docker

docker network ls docker network create --driver bridge appnet docker run -d --network appnet --name web nginx # имена резолвятся внутри сети docker network inspect appnet | grep -A3 IPv4

Внутри user-сети контейнеры видят друг друга по именам. Свои запреты — в DOCKER-USER, INPUT докер игнорирует.

Тома и данные

docker volume create appdata docker run -d -v appdata:/data nginx docker volume ls / docker volume inspect appdata # бэкап тома: docker run --rm -v appdata:/data -v $(pwd):/b alpine tar -czf /b/appdata.tgz /data

Данные в томах, не в слоях контейнера. Убил контейнер — том жив. down -v — единственная команда, о которой пожалеешь.

Registry и образы

docker tag web:1.0 registry.local/web:1.0 docker push registry.local/web:1.0 docker images / docker rmi ID docker system df # кто съел диск docker system prune -a # чистка (спросит подтверждение!)

Диагностика контейнеров

docker ps -a # включая мёртвые (там причины!) docker logs --tail 50 web docker exec -it web sh docker inspect web | grep -A5 State docker stats --no-stream # CPU/память живьём

Kubernetes

Деплойменты, сервисы, ingress, Helm.

k3s за 5 минут

curl -sfL https://get.k3s.io | sh - sudo k3s kubectl get nodes export KUBECONFIG=/etc/rancher/k3s/k3s.yaml # для внешнего kubectl

k3s — полноценный K8s в одном бинарнике. Для учёбы и edge — то, что надо; дальше — полный дистрибутив.

Deploy, Service, Ingress

kubectl create deploy web --image=nginx --replicas=2 kubectl expose deploy web --port=80 --type=ClusterIP kubectl get pods -o wide kubectl logs deploy/web -f kubectl port-forward svc/web 8080:80 # быстрый доступ без ingress

Конфиги и секреты

kubectl create configmap app --from-file=nginx.conf kubectl create secret generic db --from-literal=password=... # в Pod: envFrom configMapRef/secretRef или volumeMounts kubectl get secrets # base64 — это кодировка, НЕ шифрование!

Секреты в git — только через sealed-secrets, vault или внешний менеджер. Base64 читает кто угодно.

Неймспейсы и контексты

kubectl create ns staging kubectl config set-context --current --namespace=staging # работать в нём kubectl config get-contexts kubectl api-resources | head -30 # что вообще умеет кластер

Helm: пакетник для K8s

helm repo add bitnami https://charts.bitnami.com/bitnami helm install web bitnami/nginx --set service.type=NodePort helm list -A helm rollback web 1 # откат релиза

Terraform

Состояние, импорт, окружения.

Цикл и состояние

terraform init terraform plan -out=tfplan # что изменится — читай внимательно! terraform apply tfplan terraform state list # чем управляет terraform output # выходные значения (IP стендов!)

tfstate — святое: в git не класть (там секреты), хранить в backend (S3/PG) с локом.

Импорт живого и окружения

terraform import proxmox_vm.stand 100 # забрать существующую ВМ под управление terraform workspace new staging terraform workspace select prod terraform destroy -target=module.old # точечный снос

labspin против Terraform

labspinИмперативный скрипт: поднял, проверил, отчитался. Идеален для учебных стендов
TerraformДекларативное состояние: plan → apply → дрейф виден. Для долгоживущей инфры
