Как читать сад

Пять минут — и язык сетевых протоколов перестанет быть магией.

Что такое RFC

RFC (Request for Comments) — рабочие документы, в которых описаны все стандарты интернета. Первый вышел в 1969 году. TCP, IP, HTTP, DNS — всё, по чему ходит ваш трафик, однажды было чьим-то RFC. Документы бесплатны и открыты: их пишет сообщество IETF.

Почему растения

Протоколы не живут отдельно — они прорастают друг из друга. HTTP невозможен без TCP, TCP без IP. Поэтому сад: деревья — фундамент (IPv4, TLS), лианы — то, что обвивает фундамент (TCP, SSH), цветы — то, что распускается для человека (HTTP, DNS).

Легенда сада

Размер растения — количество связей с другими протоколами. Чем важнее узел, тем крупнее крона.
Цвет линий — градиент между цветами двух связанных протоколов; пунктир означает «зависит от».
Частицы — путь данных: от прикладного уровня вниз к сети.

Статусы растений

активен  — стандарт живой, используйте смело.  обновлён  — работает, но есть более новая версия.  устарел  — музейный экспонат: FTP всё ещё где-то растёт.

Пример: что происходит, когда вы открываете сайт

вы вводите google.com → DNS (RFC 1035) превращает имя в IP-адрес → браузер открывает TCP-соединение (RFC 793) → оборачивает его в TLS-шифрование (RFC 8446) → отправляет HTTP/2-запрос (RFC 7540) → всё это бегает по IPv4 или IPv6 (RFC 791 / 8200)

В саду этот путь виден глазами частиц, бегущих по линиям зависимостей: HTTP → TCP → IPv4 → ARP.
